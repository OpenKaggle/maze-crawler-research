# Evaluation terms and version lineage

This project keeps implementation history and evaluation evidence separate from
official competition records. The terms below make that boundary explicit.

## Experiment variants

Names such as `v51`, `v67`, `v71`, `v73`, and `v101` identify an implementation
revision or candidate family. They are not rankings, guarantees of improvement,
or a claim that the version was an official submission. A release should point
to its source file, parent/baseline when known, and evaluation receipt.

## Local paired evaluation

A local paired evaluation runs named candidates in a controlled local runner
with declared seeds, ruleset, side assignment, and metric. It is useful for
comparing candidate behaviour under the same conditions. A result should state
the two participants, run count, seed policy, code revision, and aggregate
outcome. It is not an official leaderboard result.

## Local self-play simulation

A local self-play simulation is a trace or summary generated by this project's
own local runner. It may compare revisions of this project to one another, but
it is never described as a server replay or as an organizer-provided record.
When released as a large research artifact, it carries a provenance manifest and
SHA-256 file inventory.

## Hosted-submission observation

A hosted-submission observation records the outcome or evidence produced after
the project's own candidate was submitted to the competition platform. It stays
separate from local simulation results and does not include copied raw platform
replays. The released evidence states its source category, public competition
link, candidate revision, and any available platform identifier.

## Official records and third-party work

Official inputs, server-downloaded replays, competitor replays, leaderboard
exports, and third-party kernels are external material. This repository records
their public links, identifiers, and derived analyses where useful, but does not
mirror them as project source or artifact bytes.
